# 个人任务看板（Personal Task Board）

一个纯前端、单用户的浏览器任务看板。用于快速记录个人任务，在「待处理 / 进行中 / 已完成」之间流转，并把数据保存在浏览器本地，刷新页面不会丢失。

> **项目状态：第一版 P0 功能与验收检查已完成。** 已支持新建、编辑、删除确认、快捷状态流转、深浅色主题、保存成功 Toast 和 `localStorage` 持久化；单元测试、React 组件测试、360px 弹窗和键盘流程均已验证。剩余工作是跨浏览器抽查和最终清理。第一版范围与验收标准以 [PRD.md](PRD.md) 为准。

## 项目用途

适合：

- 想在一个页面里管理 5–30 条个人任务的学生、独立开发者或知识工作者。
- 不想注册账号、不想联网、希望数据只留在本机的用户。
- 需要一个比便签更清晰、比大型项目管理工具更轻量的任务清单的人。

不适合：

- 需要多人协作、任务指派、评论或权限管理的团队。
- 需要跨设备、跨浏览器自动同步的用户。
- 需要审批流、工时统计、审计日志等企业能力的场景。

## 主要功能（第一版目标）

> 以下是第一版的完整目标。当前新建、编辑、删除确认、快捷状态流转、深浅色主题、表单校验、保存成功 Toast 和 `localStorage` 持久化均已接入；React 组件测试和 360px 键盘流程已覆盖。

### 任务管理

- **新增**：填写标题（必填）、描述（可选）和状态，默认状态为「待处理」。
- **编辑**：修改标题、描述和状态，保存后更新修改时间。
- **删除**：删除前必须经过确认，避免误删。

### 状态与筛选

- 三种状态：待处理、进行中、已完成。
- 顶部筛选标签：全部、待处理、进行中、已完成，并显示各状态数量。
- 支持快捷流转：待处理 → 进行中 → 已完成；已完成也可以重新打开。
- 当前筛选没有任务时显示空状态。

### 本地持久化

- 使用浏览器 `localStorage` 保存任务。
- 刷新页面，或关闭浏览器后重新打开应用，数据仍然存在；前提是同一浏览器配置文件、同一 origin，且没有清除站点数据。
- 不依赖后端，不发送网络请求。

### 用户反馈

- **保存成功提示**：新增或编辑成功后显示 Toast，例如「任务已创建」「修改已保存」。
- **删除前确认**：删除时弹出确认框，显示任务标题，并明确提示删除后无法恢复。
- **额外反馈**：表单校验错误、存储失败提示、空状态提示。

### 基础体验

- 响应式布局，适配桌面和 360px 以上的移动端宽度。
- 支持键盘操作，弹窗打开后聚焦到合适的位置；取消时焦点回到触发按钮，确认删除后触发按钮已移除，焦点回退到任务列表标题。
- Toast 使用 `aria-live`，确认框使用可访问的对话框语义。

### 深浅色主题

- 页头提供主题切换按钮，支持浅色和深色模式，按钮暴露 `aria-pressed` 状态。
- 初始主题优先使用已保存的偏好，其次跟随系统 `prefers-color-scheme`，最后回退浅色。
- 主题偏好保存在 `personal-task-board.theme`，刷新页面后保持；该键与任务数据完全分离。
- 主题切换只影响样式，不改变任务、筛选或持久化数据，不发起网络请求。
- 深色模式下卡片、筛选、表单、弹窗、Toast、状态徽章和空状态均保持可读。

## 技术栈

第一版计划使用：

- **Vite**：本地开发与构建。
- **React + TypeScript**：页面组件与任务数据模型。
- **原生 CSS**：布局、主题变量和响应式样式。
- **localStorage**：任务和主题偏好的本地持久化。
- **Vitest + React Testing Library**：纯函数、组件交互、主题和异常路径测试。

第一版不引入 UI 组件库、路由库或全局状态管理库，避免为一个小型单页应用增加不必要的依赖。

## 本地启动步骤

### 环境要求

- Node.js 20.19+（或 22.12+）。
- pnpm 10+（本项目使用 pnpm 11）。

### 安装依赖

```bash
pnpm install
```

### 启动开发服务器

```bash
pnpm dev
```

打开终端输出的本地地址，通常是 `http://localhost:5173`。如果端口被占用，Vite 会自动选择其他端口，请以终端输出为准。

> 新增、编辑、删除确认和快捷状态流转均已可用；删除后数据无法恢复，操作前会二次确认。

### 运行测试

```bash
pnpm test
```

当前共 **45 项测试**（6 个测试文件），覆盖任务统计、状态筛选、状态流转、排序、日期格式化、表单校验、主题偏好、`localStorage` 读写和异常处理，以及新增、编辑、删除确认、Toast、键盘取消和空状态等组件流程。360px 弹窗、主题和键盘流程另通过浏览器手工检查。

### 生产构建（可选，不等于部署）

```bash
pnpm build
pnpm preview
```

`preview` 只用于本地检查构建产物，不用于部署上线。

## 合成数据说明

### 什么是合成数据

合成数据指为了开发、演示和自动化测试而编造的示例任务，不包含任何真实个人信息、账号、公司内部信息或敏感内容。

### 放在哪里

合成数据放在 `src/data/seedTasks.ts`，由开发预览和自动化测试共用。当前包含 6 条任务，覆盖三种状态：

| 标题 | 状态 | 描述示例 |
| --- | --- | --- |
| 整理本周阅读清单 | 待处理 | 从收藏夹里挑出 3 篇文章，安排到本周 |
| 预约牙医 | 待处理 | 查找附近的诊所并确认营业时间 |
| 写项目 README | 进行中 | 补充安装、启动和已知问题说明 |
| 修复筛选空状态 | 进行中 | 检查切换标签时是否展示正确的空状态 |
| 完成周报 | 已完成 | 汇总本周进展和下周计划 |
| 清理下载目录 | 已完成 | 删除临时安装包和过期文件 |

### 使用规则

- 应用默认从空看板开始，**不会自动把合成数据写入用户的 `localStorage`**。
- 自动化测试通过 `import` 直接使用 fixture，不依赖浏览器里已有的真实数据。
- 开发环境访问 `http://localhost:5173/?preview=1` 可查看任务卡片布局；该模式明确标注「布局预览」，不写入本地存储，操作按钮保持禁用。
- 任何演示模式都应使用独立的数据键，或明确提示会覆盖当前看板，不能静默污染真实任务。
- 合成数据中不得出现真实姓名、邮箱、手机号、公司名称、访问令牌等内容。
- 清理合成数据时，优先使用浏览器开发者工具删除对应的独立存储键或清除站点数据；如果后续提供应用内清空操作，必须经过确认。

## 数据存储

> 新增、编辑、删除和快捷状态流转都会立即写入 `localStorage`；刷新后可从同一浏览器、同一 origin 恢复。写入失败时会保留当前会话内的任务，并提示刷新后可能丢失，不会显示保存成功。

- 任务存储键：`personal-task-board.v1`。
- 主题偏好键：`personal-task-board.theme`，值为 `light` 或 `dark`。
- 存储位置：当前浏览器、当前站点 origin 下的 `localStorage`。
- 数据格式：任务使用带版本号的 JSON，例如 `{ "version": 1, "tasks": [...] }`；主题偏好是独立字符串。
- 数据范围：只存在当前浏览器配置文件中；换浏览器、换设备、换端口或清除站点数据后不可见。
- 不写入 Cookie，不发送到服务器，不接入统计或广告脚本。

任务数据结构：

```ts
export type TaskStatus = 'todo' | 'doing' | 'done';

export interface Task {
  id: string;
  title: string;
  description: string;
  status: TaskStatus;
  createdAt: string;
  updatedAt: string;
  completedAt: string | null;
}
```

### 第一版产品边界

- 不支持账号、登录、后端接口、云同步和多用户协作。
- 不支持跨设备同步；数据只属于当前浏览器配置文件。
- 不支持撤销删除；删除确认后无法恢复。
- 不支持搜索、用户自定义排序、标签、截止日期、提醒、附件、子任务和重复任务。
- 不支持导入/导出 JSON；清除浏览器数据后无法从应用内恢复。
- 不支持拖拽排序或三列看板布局；第一版使用列表 + 状态筛选，优先保证核心流程。
- 不做部署上线，不提供公网访问地址。

### 已知技术限制

- `localStorage` 通常只有约 5MB，容量满时写入会失败；应用应提示错误，而不是静默丢失。
- 浏览器隐私模式、禁用了站点存储或策略限制下，`localStorage` 可能不可用。
- 主题偏好只保存在当前 origin；清除站点数据后会重新跟随系统主题，主题偏好写入失败时仅当前会话生效。
- 更换端口会改变 origin，导致读不到旧端口下的数据。
- 多标签页同时修改时，第一版接受「最后写入覆盖」，不做实时同步。
- 任务数量很大（例如上千条）时，列表渲染和筛选可能变慢；第一版以 200 条以内为主要目标。
- `crypto.randomUUID()` 需要安全上下文；本地 `localhost` 可用，其他环境需要降级生成 ID。
- 仅计划支持较新的 Chrome、Edge、Firefox 和 Safari；旧版浏览器的 `<dialog>` 兼容性需要单独验证。
- 已有单元测试、React 组件测试和 360px 手工检查；尚无自动化端到端测试和完整的跨浏览器无障碍审计。
